# Набор для Kimi: протокол монтажа Shorts

Содержимое переносимое: это текст и JSON, без привязки к Claude Code.

| Файл | Зачем |
|---|---|
| `01_SYSTEM_PROMPT.md` | Вставить в системный промпт / первое сообщение Kimi |
| `02_MONTAGE_PROTOCOL.md` | Полный протокол: последовательно, lint, verify, лимиты, сжатие |
| `03_TASK_CONTINUE.md` | Готовая задача «доделать 16 видео» |
| `04_kimi-code-config.toml` | Шаблон config.toml для Kimi Code CLI |
| `manifest.template.json` | Шаблон манифеста (источник правды по статусам) |

## Как использовать в Kimi
1. Скопировать папку на рабочий стол (или скачать ZIP с GitHub: Code → Download ZIP).
2. Вставить `01_SYSTEM_PROMPT.md` в системный промпт, приложить `02_MONTAGE_PROTOCOL.md` как файл/контекст.
3. Отправить `03_TASK_CONTINUE.md` как первое сообщение.

## Kimi Code (CLI / десктоп / VS Code): что важно для протокола
По официальной документации Kimi Code:
- Модель `k3.1-pro`: контекст до 1 048 576 токенов, только режим мышления (`low`/`high`/`max`, по умолчанию `high`), вход текст, картинки, видео. Быстрая версия `k3.1-pro-highspeed` в 2–3 раза быстрее, но расходует примерно вдвое больше.
- Тариф: K3.1 Pro с Plus и выше, 1M контекста с Pro и выше; быстрая версия с Pro. Точные лимиты запросов по тарифам на загруженных страницах не видны (вкладка «Права участников» не приложена), поэтому бюджет «5 видео за окно» остаётся оценкой.
- Не менять модель и уровень мышления внутри сессии: кэш контекста теряется, расход растёт. Это совпадает с нашим правилом «одно видео в свежем контексте».
- Настройки в `~/.kimi-code/config.toml` (шаблон: `04_kimi-code-config.toml`). Там есть `[loop_control] max_attempts_per_step` и `reserved_context_size`, `[task] max_running_tasks` (наш потолок параллели = 2), правила разрешений и хуки (`PreToolUse` и др.).
- CLI: `/model` смена модели, `/login`, `/provider`, `kimi migrate` (перенос из старого kimi-cli; OAuth-вход и MCP-авторизацию нужно сделать заново).
- Режим плана: `default_plan_mode`, подходит для шага «lint плана до рендера».

## Что может отличаться от Claude Code
- Команды вроде `/compact`, `/usage` и планирование возобновления (`send_later`): в загруженных страницах документации их нет. Проверьте в Kimi Code командой `/help`; если их нет, сжатие делается сводкой в новую сессию (`manifest.json` + `RESUME.md`), а расход лимита смотрится в личном кабинете.
- Субагенты: в конфиге есть `[task]` с фоновыми задачами, но их семантику (синхронный вызов, отчёт) я по загруженным страницам не проверил.
